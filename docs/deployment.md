# Deployment (Ubuntu + nginx)

Family Tree Studio is fully static after the build: `dist/` contains plain
HTML/CSS/JS and needs no Node process at runtime. Node is required only
**at build time** (Node 22 LTS or newer). The recommended setup is nginx
serving `dist/` at `https://treestudio.app`.

Paths below assume Ubuntu 22.04/24.04 and the project in `/opt/family-tree-studio`.

## What the build produces

```
dist/
  index.html            /            home page, English (pre-rendered)
  ru/index.html         /ru/         home page, Russian (pre-rendered)
  editor/index.html     /editor/     editor, English
  ru/editor/index.html  /ru/editor/  editor, Russian
  viewer/index.html     /viewer/     visualizer, English
  ru/viewer/index.html  /ru/viewer/  visualizer, Russian
  assets/               hashed JS/CSS/fonts/workers (immutable)
  sitemap.xml robots.txt favicon.* apple-touch-icon.png og-image.jpg
```

Every page carries its own title, description, canonical URL, `hreflang`
(en / ru / x-default = English), Open Graph, Twitter card and JSON-LD. All of it is
generated by `scripts/pages.ts` from `meta.*` in `messages/{ru,en}.json`;
the origin is `SITE_ORIGIN` in the same file — change it there if the domain
changes. Nothing is loaded from third-party hosts (fonts are self-hosted).

## 1. Initial deployment

### Install prerequisites

```bash
sudo apt update
sudo apt install -y nginx rsync

# Node.js 22 LTS (build-time only) via NodeSource
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
node --version   # v22+
```

### Get the code and build

```bash
sudo mkdir -p /opt/family-tree-studio
sudo chown "$USER": /opt/family-tree-studio

# copy the project to the server (from your machine):
#   rsync -a --delete --exclude node_modules --exclude dist \
#     ./ user@server:/opt/family-tree-studio/
# or clone it:
#   git clone <repo-url> /opt/family-tree-studio

cd /opt/family-tree-studio
npm ci            # reproducible install from package-lock.json
npm run build     # typecheck + build into dist/
```

### Configure nginx

`/etc/nginx/sites-available/family-tree-studio`:

```nginx
server {
    listen 80;
    server_name treestudio.app www.treestudio.app;

    root /opt/family-tree-studio/dist;
    index index.html;

    # Pages are directories with an index.html; /editor redirects to /editor/.
    # HTML is always revalidated so a new release is picked up on the next load.
    location / {
        try_files $uri $uri/ =404;
        add_header Cache-Control "no-cache";
    }

    # Hashed assets are immutable — cache aggressively
    location /assets/ {
        add_header Cache-Control "public, max-age=31536000, immutable";
    }

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
}
```

```bash
sudo ln -s /etc/nginx/sites-available/family-tree-studio /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
sudo apt install -y certbot python3-certbot-nginx && sudo certbot --nginx -d treestudio.app -d www.treestudio.app
```

Open `https://treestudio.app/` — the home page with two buttons; the
visualizer draws the demo tree on its own.

No backend, no database, nothing else to run: GEDCOM files are parsed
entirely in the browser and never leave the client. The editor keeps its
draft in the browser's IndexedDB, which is per origin — moving to another
domain starts with an empty editor (users can carry trees over as GEDCOM or
JSON backups).

### Optional: redirect the old visualizer domain

The visualizer used to live at `https://gedtree.ru` (`/` Russian, `/en/`
English). To keep old links working, point that domain at the new pages:

```nginx
server {
    listen 80;
    server_name gedtree.ru www.gedtree.ru;
    location = /en/ { return 301 https://treestudio.app/viewer/; }
    location /      { return 301 https://treestudio.app/ru/viewer/; }
}
```

### Search engines

After the first deploy, register `treestudio.app` in
[Google Search Console](https://search.google.com/search-console) and
[Yandex.Webmaster](https://webmaster.yandex.ru/) and submit
`https://treestudio.app/sitemap.xml` — a manual, one-time step.

## 2. Updating to a new version

Upload the new code, reinstall dependencies and rebuild; nginx serves the new
files right away — **no restart is required** for static content.

```bash
cd /opt/family-tree-studio
# upload beforehand (rsync as above, keeping node_modules and dist) or: git pull
npm ci
npm run build
```

Asset filenames are content-hashed and HTML is served with `no-cache`, so
browsers get the new version on the next page load.

### Zero-downtime variant

`npm run build` clears `dist/` before writing, so for a few seconds nginx
may serve a half-written build. To avoid that, build aside and swap:

```bash
#!/usr/bin/env bash
# /opt/family-tree-studio/update.sh — run after every upload
set -euo pipefail
cd /opt/family-tree-studio
npm ci
npm run typecheck
npx vite build --outDir dist-next
rm -rf dist-prev
mv dist dist-prev 2>/dev/null || true
mv dist-next dist
echo "Deployed. Previous build kept in dist-prev/ (rollback: swap back)."
```

Rollback after a bad deploy: `mv dist dist-bad && mv dist-prev dist`.
